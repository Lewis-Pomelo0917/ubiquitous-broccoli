# AI Watch runtime and handoff contract

This feature is a Windows x64, local-first updater. Source collection requires an internet connection; summary selection runs locally and does not call GPT, Codex, a remote model API, or a model downloader.

## Data flow and protection

1. While Cubic is running (including in the tray), the Tauri scheduler checks at startup and every 15 minutes whether an update is due. The worker itself records the next due time in the status file (`next_due_unix`): tomorrow at 06:00 local time (at least six hours later) after a good run, two hours later when most sources failed, and 30 min / 1 h / 2 h / 4 h / 6 h (capped) after consecutive failed runs. A persistent failure of a few sources therefore no longer causes hourly re-runs. The refresh button on the home card asks the scheduler to run now. Exiting Cubic stops the scheduler; there is no service, auto-start, or background process left behind. A status without `next_due_unix` (written by an earlier release) is treated as due once, so an upgrade refreshes the card at its first launch. A worker that does not finish within 35 minutes is terminated, and a worker that cannot start or dies without writing a result is reported as `failed` (never left on "updating"; the last lines it printed are kept as `error_detail`). The worker exits as soon as its result is written, even if a fetch is still waiting on a slow server.
2. The packaged Python 3.13 standard-library runtime reads the bundled 91-entry public source registry and reuses the original rules-first `ai_radar` collector. Sources are fetched concurrently (eight workers, at most two per host, 20-30 s per source) while all SQLite work stays on one thread. Its snapshots and update status live only in Tauri's per-user `app_local_data_dir`; the collector does not read `accounts.json`, the source project's databases, backups, logs, or user files.
3. Pages are read as text, one line per block element (inline markup is merged, navigation/footers/icon glyphs are dropped, `<time datetime>` becomes an ISO date); Atom/RSS feeds and Statuspage JSON are rendered as dated lines. Listings that print an entry's headline or category above its date are cut at the entry's own container (article, list item or card link) when at least two entries on the page show that pattern, so a headline stays with its date. A page that is a browser-verification wall or has no readable text is reported as a failed source with its reason instead of counting as "checked" (only HTML pages are screened this way; a parsed feed or status document is real content). Deterministic rules detect lines that are new compared with the previous snapshot (moved lines are not news), group them under their date headings, keep source URLs, deep links and dates, filter stale dated changes, flag missing dates as undated/observe, and deduplicate exact normalized evidence. Explicit future effective dates (a retirement or price change named in the text) are kept and used as the event date. The first snapshot of a source is backfilled with entries dated in the last seven days so the card is useful on day one; a snapshot written by an older text format (`PRAGMA user_version` below 3) is discarded once and re-baselined.
4. Event titles, types, priorities, dates and links come from rules. For the events the home card can show (up to six), the rules split the evidence into candidate sentences: verbatim, at most 160 characters, headline excluded, and for an uncertain source only sentences that keep its uncertainty wording. Qwen is shown the numbered sentences and asked which one best states what changed; a per-call JSON-schema grammar (`{"choice": <one of 1..n>}`) allows nothing else, so the model never writes text and cannot garble a copy. The model does not create events, labels, dates, amounts, priorities, titles, or sources. The chosen sentence is re-checked as a literal single-line substring of the evidence before it is stored. With only one candidate sentence the model is not run. Instruction-like source text (for example "ignore previous instructions") is not sent to the model; ordinary news about system prompts is. If the model fails to start, answers badly, or runs out of its time budget, that event keeps the first candidate sentence (`summary_mode: "rule-v1"`, also verbatim evidence); after two consecutive model failures the remaining events use rule sentences without calling the model again. Model trouble is reported (`model_state: "unavailable"`, `model_error`) but never blocks the news.
5. A validated version-1 feed is written with a same-directory temporary file and atomic replacement. The feed records `collected_through`; events collected by a cycle that was interrupted or failed are published by the next cycle. If every source fails, or the new feed fails validation, the previous `ai-intelligence.json` is not replaced and the status says `failed`. The feed holds at most 50 events from the last 30 days; when there are more, news still inside its home-card display window is kept first whatever its priority, so a pile of older high-priority items cannot push today's news out, and `new_items` counts what was actually published. The files are replaced with a short retry (about three seconds) to ride out antivirus or indexer locks on Windows. A damaged feed is set aside by the app as `ai-intelligence.json.corrupt-<time>` and replaced by the packaged seed at start, and the worker rebuilds the news from its own database; a state database that fails an integrity check at open is set aside as `state.sqlite3.corrupt-<time>` (the three newest are kept) and rebuilt, while a database that is merely busy, locked or full is never treated as damaged and never discarded. Partial source failures, total failure, a successful no-new-items check, stale data, and an update in progress have separate status states.

The app-data directory is keyed by the unchanged Tauri identifier `com.tradedesk.app`, so moving or renaming the EXE for the same Windows user does not move the feed, SQLite snapshots, or model cache. First launch seeds `ai-intelligence.json` only when it is absent; an existing valid feed is never replaced by the packaged seed. Notes, calculator history, theme, and other WebView storage are not migrated to a different computer. The collector's primary HTTP transport is Python's bundled standard library; the reused optional Schannel/TLS fallback calls Windows `curl.exe` when present. If that OS fallback is unavailable, affected sources are reported as failed/partial rather than as “no news.”

### Troubleshooting a quiet or failing card

| Where | What it tells you |
| --- | --- |
| Badge and tooltip on the home card | State, last successful check, failed sources by reason (blocked, timeout, DNS, TLS, page missing, needs JavaScript), model state |
| `ai-watch-status.json` in the app-data folder | Everything above plus `failed_samples`, `next_due_unix`, `consecutive_failures`, `model_error`, `error_detail` |
| `ai-watch\last-run.json` in the app-data folder | One row per source for the last cycle: outcome, reason, seconds, new events |

## Single-file Windows package

The final Windows x64 `Cubic.exe` is a normal Tauri PE executable with a verified local-runtime payload appended to it. `tauri build --no-bundle` by itself is only the base application; `scripts/build_ai_runtime.ps1` verifies the locked resources, runs the synthetic model check, and appends the payload. The end-user package is one EXE: it contains the Qwen weights, Python worker/runtime, llama.cpp CPU inference files, public source registry, licenses, schema, and optional initial feed seed. On first run, Cubic validates the payload and releases the managed runtime to `app_local_data_dir/ai-runtime`; on later starts it verifies and reuses that cache. Corrupt or interrupted component extraction is rebuilt through a staging directory; feed and user storage are outside that managed component cache.

The package does not contain a third-party model application, and the end user does not download the model or install Python. Windows WebView2 remains a platform prerequisite. The initial feed seed is optional at build time and is never committed to this repository.

### Reproducible build steps

1. Create a registered, ignored `work/<task>/TASK.md`, a clean `work/<task>/build/frontend` copied from the current tracked frontend resources, and a separate Tauri merge config containing only `build.frontendDist: "../../../work/<task>/build/frontend"`. Resolve it from `development/desktop/src-tauri` and verify `index.html`, logos, fonts, and `pantone-data.js`. Use a task-specific Cargo target directory so no prior candidate is overwritten:

   ```powershell
   New-Item -ItemType Directory .\work\<task>\build\target | Out-Null
   $env:CARGO_TARGET_DIR = (Resolve-Path .\work\<task>\build\target).Path
   Set-Location .\development\desktop
   node .\node_modules\@tauri-apps\cli\tauri.js build --no-bundle --ci --config "..\..\work\<task>\build\tauri.frontend.json"
   Set-Location ..\..
   ```

2. Append the locked runtime. Use new ignored `work/` directories; do not point these paths at `outputs/`:

   ```powershell
   .\development\desktop\scripts\build_ai_runtime.ps1 `
     -ResourceCache .\work\ai-runtime-resources `
     -BaseExe .\work\<task>\build\target\release\Cubic.exe `
     -OutputExe .\work\ai-runtime-build\Cubic.exe `
     -WorkDir .\work\ai-runtime-build\stage `
     -VCRedistDir "$env:VCINSTALLDIR\Redist\MSVC\14.51.36231\x64\Microsoft.VC145.CRT"
   ```

   Also pass `-VCRedistDir` pointing to the licensed build host's matching `Microsoft.VC145.CRT` directory. For a private local seed only, the builder may pass `-InitialFeedPath` pointing to a validated version-1 feed. Do not add that file or its path to the commit. The script refuses to overwrite existing staging or output paths, rechecks hashes, tests the embedded Python worker/model against synthetic inputs, and uses `pack_ai_runtime.py` to verify the final payload and PE architecture.

## Frontend contract for Claude Code

- Tauri `read_ai_feed` returns the existing version-1 JSON schema from app-local data. Existing `events`, source URLs, evidence, `published_at`, priorities and `confidence` remain authoritative; the feed also carries `collected_through` and `title` is now a readable headline taken from the evidence.
- `read_ai_status` returns `state`, `message`, source counts, `last_success_at`/`last_attempt_at` and the worker's extra fields (`failure_kinds`, `failed_samples`, `model_state`, `model_error`, `next_due_unix`, `consecutive_failures`). States are `preparing`, `updating`, `updated`, `no_new_items`, `partial`, `failed`, `interrupted`, and `unsupported`. A read/collection failure must not be presented as “no news”; `partial` and `failed` retain the last successful feed. Rust preserves fields it does not know when it rewrites the file.
- `refresh_ai_news` asks the scheduler to check now and returns `{"accepted": bool, "reason"?}`; the card's refresh button is its only caller. It does not collect anything itself.
- By default the card shows three items chosen by importance, not by discovery time: events whose news date (`published_at` when present, otherwise the day they were found) is within seven days for P0/P1 or three days for P2/P3, ordered by priority, then recency, then confidence, skipping a repeated title. The viewer can narrow this with category buttons, a range (近期重点 = those windows, 近 7 天, 近 30 天), and a sort: 优先级优先 (the default, the order above) or 最新优先 (news date first, a time on the publication date or else the discovery time within a day; upcoming dates count as today; then priority). Filtering, sorting and the repeated-title check run before the collapsed card takes its three, and 展开全部 lists every match. The sort only changes the order, never which copy of a repeated title is shown, and the event key breaks remaining ties. The choice is kept per machine in `localStorage` under `tradeDesk.aiWatchView` (`group`, `range`, `sort`, `expanded`); a missing or unknown value falls back to the default. Only the first six of the default order at update time go to the model, so items further down usually carry rule excerpts (also verbatim evidence). Day labels are 今天 / 昨天 / n 天前 / 月日, and an upcoming effective date reads “月日生效”. `development/desktop/tests/fixtures/display-selection.json` is checked by both the Python worker tests and the frontend regression test; change both implementations together.
- `summary` with `summary_mode: "extractive-v1"` is a model-selected excerpt and with `"rule-v1"` a rule-selected one; both are guaranteed to be literal substrings of `evidence`. Anything else falls back to the start of the evidence, and a summary that merely repeats the title is not shown.
- The existing home-card hooks `.home-ai-card`, `.home-ai-day`, `.home-ai-events`, `.home-ai-item`, `.home-ai-priority`, `.home-ai-source`, and `.home-ai-time` are adjustable. Keep new styling within `.home-ai-*`, preserve the existing theme variables and responsive layout, render feed text with `textContent`, and validate links with the current HTTP/HTTPS allowlist.
- Frontend polling is read-only. Do not start collection from a timer in JavaScript, write feed/status files from the browser, raise the three-item default (more items only when the viewer expands the card), or relabel a failure as an empty result.

## Known limits

Qwen3-0.6B only picks among sentences of the displayed evidence, not a fact checker or a replacement for GPT; its pick is a numbered choice, so the quality of a pick (as opposed to its validity) was not measured on the real model in this change. The rules decide freshness, category, priority, titles and deduplication. News collection still needs network access; only inference is offline. Pages are read from their HTML, so sources that render everything with JavaScript or sit behind a browser-verification wall cannot be read and are reported as failed with their reason. The registry was reviewed as a snapshot of public URLs; sites move, so `last-run.json` is the place to see which entries no longer work. Hardware-specific inference speed, WebView2 presence, native display, tray behavior, and full exit behavior must be reported separately from source and packaging checks.
